Privacy policy

Everything is OK · yt.japharsworld.com and eiok.cc · updated 2026-11-13

In short: this site has no accounts, no cookies, no third-party analytics scripts and no ads, and it never asks for your VRChat name. It stores and logs which videos were found and played, under a room number, with no name attached. It does not keep your IP address: it checks the address against its limits as each request arrives and afterwards remembers only a daily code made from it (see IP addresses and limits). Older web server log lines are the one exception (see Logs).

What this site keeps

  • Search results and plays. Video ID, public title, channel, length, whether live and the start of the description, under a room number and time, with no name or IP address. A pasted YouTube link's video is stored and logged the same way. No time limit: a result stays until its slot is reused, a room's last played video until its next play.
  • Video copies. With their video ID, quality, length, times and build details, nothing about who watched. Removed here 72 hours after their last upload, sooner when space is short. The home server keeps its copies until it needs the space.
  • Captions. Stored by video ID and reused for 7 days, then deleted (checked every hour) and fetched again when needed.
  • Working files. Video IDs and Tunelio links of current and recent plays, and videos to send elsewhere for a while. Nothing about visitors.
  • Usage totals. Per day or hour, no end date: joins, searches, plays, captions, how many videos had captions, languages, quality picks, Channels redirects, video reports (Resync, a stalled video reloaded, the world testers' problem reports, by kind only), how videos were served, and PC or Quest (from the software name or the form of the video's web address, not an IP address). Never search text, video IDs or IP addresses. Public VRChat numbers for the world and its group too.
  • Play reports. For each video play, the world also reports how long it took until the first picture appeared, in coarse steps (within 5, 10, 20, 30, 45, 60 or 90 seconds, or longer), or, when the play failed, how it ended, by kind only (for example, the player gave up before or after the picture appeared, or the room moved on first). Each report says only whether it came from PC or Quest/Android, whether the player is one of the world's testers, and which kind of playback route or source it used. It holds no room, video or ticket, and nothing about you.

Logs

Each request's kind, response code and duration. For a search: language, length, kinds of characters, PC or Quest. For plays, captions and reports: room number (instances can share one), ticket number, video ID, how it was served and the first 80 characters of the player's software name. A world tester's play report is logged as well, by kind only. No search text, IP addresses or VRChat account. The web server in front of the service logs no request details, and in its connection errors it writes "client" in place of the visitor's address.

Exceptions: the firewall logs blocked packets' addresses, which can include visitors'. A rare search library warning can contain search text. Logs have no time limit; the oldest go only at a size cap. Older web server log lines, written before this was changed, can still hold a visitor's IP address and full request address, including search text.

IP addresses and limits

So that one visitor can't flood the service or use up what everyone shares, each request is checked against limits as it arrives: searches, ticket loads and play reports a minute, and how many new videos each visitor starts a day. Afterwards the server remembers only a daily code made from your address with a secret key. The key is random, held in memory only, and replaced at the start of each day (America/Chicago time); once it is gone, the day's codes can't be traced back to an address. The codes and the counts under them are in memory only, never written to disk, logged or sent anywhere, and a restart clears them. A code is kept for up to two minutes after your last request (for the per-minute limits); until the end of the day (for the daily limit); while a video you started is being prepared in higher qualities (usually seconds, at most 12 hours, so they count toward your own daily limit); and, for a code made from your address and your video player's name that tells a reload from a new viewer, 12 hours after you started the video.

YouTube API Services

This site uses YouTube API Services. By using this site, you agree to be bound by the YouTube Terms of Service. The Google Privacy Policy also applies.

  • The only Google account connected is the world owner's own, which authorized access with the YouTube scope. That access is used for one thing: to keep the unlisted playlists behind the Channels list on the owner's channel current, by reading them, adding a live stream, removing the old one, or emptying one whose stream fails a safety check.
  • The monitor also reads public information about those streams: whether they are live, their titles and channels, viewer counts and thumbnails. It keeps that information to measure how reliable each stream is. These records and the access token are stored on one server run by the owner.
  • No private data about any other YouTube user is requested, stored or shared. Visitors never sign in to Google through this site.
  • The owner can revoke this access at any time in Google account permissions, after which stored access tokens stop working.
